写代码这件事，AI 已经接过去一大半了。但写完之后呢？

提个 PR，等人 review，等 CI 变绿，改几轮意见，再等合并——这套流程里耗的时间，有时候比写代码本身还长。Anthropic 11 月 23 日发布的 Claude Ship，就是冲着这段流程来的：它让 Claude 不光写代码，还能审 PR、修问题、批合并。

先说它到底是什么。Claude Ship 不是一个工具，是三个智能体搭在一起的一套流程：

- **Code Review**，负责审 PR。它会把改动对照整个代码库看一遍，找出逻辑错误、安全问题和边界情况，核实之后再把意见贴到 PR 里。这部分之前就已经正式可用了。
- **PR Steward**，这次新上线的，负责修。CI 挂了、分支冲突了、review 里提了意见，它都会去处理，改完还会在 PR 里留言，说清楚自己改了什么、怎么回滚。
- **Claude Approvals**，也是新上线的，负责批。它读团队写在仓库里的审批策略文件，判断这个改动够不够“常规”，够常规就自己批，不够就交给人。

入口很简单：在 Claude Code 里更新到最新版，对自己的 PR 跑一个 `/ship` 命令，三个智能体就接力干活了。

听起来很顺，但有几个细节值得单独拎出来说。

第一，**批合并的权力，Anthropic 没有直接交给 AI，而是交给了团队自己写的策略文件**。哪些目录的改动可以自动批、哪些必须有人签字、每个部分需要几个人，这些规则由团队写进仓库默认分支里的一个文件。Claude Approvals 只是在这个文件划定的范围里做决定。换句话说，AI 批不批，不是它说了算，是你提前写好的规则说了算。这个设计挺关键的——它把“信不信任 AI”这个问题，变成了一个可以逐条写的配置问题。

第二，**PR Steward 不能批、也不能合并**。修归修，批归批，权限是分开的。一个智能体改了代码，另一个智能体按策略决定能不能过，互相之间有个制衡。Anthropic 自己也建议，刚开始先用“只观察”模式跑一阵子，看看它会怎么判，等摸熟了再真正放权。这个建议值得听——自动审批这种事，第一次就全开，胆子确实得大。

第三，**它不是谁都能用的**。目前只面向 Claude Team 和 Enterprise 套餐的客户，而且只支持 GitHub 上的仓库。另外，用了零数据保留配置、HIPAA 配置或者客户自管加密密钥的组织，现在用不了 Claude Ship。计费按 token 来，跑得越多花得越多，管理员可以给 Code Review 和 PR Steward 设 spending 上限。符合条件的 Enterprise 客户可以领一笔 Claude Ship 推广额度，官方说至少 1 万美元，2027 年 1 月 15 日之前领取。

这事放在更大的图景里看，意思就清楚了：AI 写代码的竞争，瓶颈已经从“写不写得出来”挪到了“审不审得完、合不合得进去”。去年大家比的是谁家模型补全更准，今年比的是谁能把从写到合并的整条链路打通。Claude Ship 就是 Anthropic 在这条链路上的押注。

对普通开发者来说，这事不用急着追。先想清楚三件事：你的团队现在卡在 review 还是卡在写代码？你们愿不愿意把审批规则写成文件、交给机器执行？以及，自动批的范围第一次划多小才安心？这三个问题想明白了，再去试 beta，心里才有底。

毕竟，能审 PR 的 AI 只是工具，敢让它批合并的团队，才是真的把流程想明白了。
