先说一个真实发生的事。一位不会写代码的博主，用 AI 做了一套个人信息管理系统，全程没自己写一行代码，最后还把代码开源了。视频在 YouTube 上，仓库在 GitHub，名字叫 tyrans/infosys，2026 年 11 月 24 日建的仓。

他的链路是这样的：先用 Claude 把需求想清楚、写成提示词；再用 WorkBuddy 生成 PHP 程序，中间修了一个搜索 bug；最后用 Muse 把程序移植到 Cloudflare Workers 上部署。需求、生成、修 bug、部署，四步走完，一个能用的应用就上线了。

仓库里到底是什么？按 README 的说法，这是一套单管理员的个人信息管理系统，分两个模块：

一个是「账号提示」，管网站、账号和密码提示。注意一个细节：系统只保存手写的密码提示，绝不保存完整密码，界面里也没有任何要求输入完整密码的入口。每次改提示，还会自动保留上一次、上上次的历史。

另一个是「私密信息」，用来存身份证号、社保号、银行卡号这类零散信息，备注用 AES-256-GCM 加密保存，密钥由主密码派生。服务器数据库里看不到明文。

原版的 PHP 实现打包放在仓库 Releases 里，叫 infosys-php-v1.0.0.zip，要求 PHP 8.1 以上，解压后放进任意 PHP 站点目录就能跑，数据存在本地的 SQLite 文件里。Cloudflare 版则是单个 Worker 加 D1 数据库，部署要用到 Node.js 和 wrangler，照着 README 的三步走：建 D1、部署、打开地址登录。

有两件事，README 写得挺实在。第一，默认密码是 123，首次登录后必须马上改，新密码至少 6 位、不能是 123；默认密码下禁止新增和修改私密信息。第二，主密码一旦忘记，私密信息无法找回，没有找回途径，也不会生成恢复码。

所以，别被「不会写代码也能做应用」这句话带偏了。门槛不是消失了，是换了地方：

需求得你自己想清楚。AI 不会替你决定这个应用到底管什么、不管什么。博主先花功夫和 Claude 把需求聊透，这一步省不掉，含糊的需求只会生成含糊的程序。

Bug 得会描述、会测试。视频里搜索功能出了 bug，是博主把现象讲清楚、让 AI 去修的。你不需要会写代码，但需要会判断：这个功能对不对、这个结果能不能用。

部署有几道坎。Cloudflare 账号、wrangler、D1 数据库，这些词对新手都不友好。README 写得算细，照着走能走通，但第一次难免磕磕绊绊。

安全这件事，我得多说两句。演示用的默认密码是 123，演示数据也是假的，别往这种练手作品里存真实密码。真要管密码，用 Vaultwarden 这类正经的密码管理工具。这个项目更适合当练手：走通「需求—生成—测试—部署」这条链，理解 AI 编程到底是怎么回事。

如果你也想试一次，可以按这个顺序来：

先把需求写成一句话，再拆成三五条具体功能。别写「做个好用的管理系统」，写「我要记 30 个网站的账号提示，能按网站名搜索，私密信息要加密」。

然后找个 AI 编程工具，把需求贴进去，让它先出方案、再出代码。方案不对先改方案，别急着跑代码。

跑起来之后，一个功能一个功能点过去。哪个不对，把现象原样描述给 AI，让它修，修完再测一遍。

最后处理安全：改掉所有默认密码，确认数据存在哪、谁能访问。练手项目别放真实信息，这条没有例外。

不会写代码的人做出应用，这事本身不稀奇了。稀奇的是，做出之后还愿意把仓库公开、把默认密码和找回不了的规则写在 README 最显眼的地方。这份坦诚，比应用本身更值得学。
