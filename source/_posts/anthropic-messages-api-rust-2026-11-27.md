Anthropic 最近在官方工程博客上讲了一件挺有意思的事：他们把 Messages API 从 Python 迁到了 Rust。11 月 25 日发的文章，作者是 Lance Martin 他们。Messages API 是什么呢，按文章里的说法，它是客户、还有 Claude Code、Cowork 这些自家应用访问 Claude 的主要方式。最早是 2023 年用 Python 写成的。

为什么要迁？流量涨得太快了。文章里给了一个数字：从 2024 年初到 2026 年秋季，API 流量增长了约 1800 倍。Python 那套东西撑是能撑，但成本摆在那儿。Rust 这边的好处也写得很具体：每请求 CPU 占用降低约 70%，首个 token 的中位时间缩短约 20%。2026 年 9 月，公开流量切到了 Rust，全程不停机，功能开发也没冻结。

写代码这部分，Claude 自己就干了不少。文章说，Claude 大约用一周写出了核心请求路径的第一版。到 2026 年 5 月，Claude 写了 Anthropic 合并代码的 80% 以上。也就是说，重写本身已经不是瓶颈了，模型写代码的速度摆在那儿。

真正卡住他们的是另一件事：怎么证明 Rust 版和 Python 版的行为是一样的。

他们一开始走的是常规路子：写集成测试。大概 700 个集成测试，到 4 月份，Rust 版通过了约 98%。看着挺像那么回事。但一上真实生产流量，情况就变了：只有约四分之一的输入，Rust 版和 Python 版跑出来的结果是一致的。

这个落差挺值得琢磨的。测试全过，不等于生产一致。测试是你自己写的，你能想到的情况就那么多；生产流量是用户真实打进来的，千奇百怪的输入、边界情况、各种奇怪组合，全在里面。98% 这个数字，测的是你准备好的那套题；四分之一这个数字，测的是现实。

Anthropic 后来换了个办法：把生产 API 本身当验证器。他们的做法叫影子流量比对。模型只跑一次，输出重放给 Rust 版，然后逐步骤比对两边的处理过程。差异只记位置和长度，不记客户原文——这点文章里特意提了，隐私上做了处理。比对出差异之后，再派智能体去修，修完继续比。

这个过程不是一蹴而就的。文章里还提了一个细节：先期只把模型输出解析改成 Rust 的时候，CPU 只降了 8% 到 10%。跟最后整条链路迁完的约 70% 比起来，差得远。意思是光改一个环节，收益有限，得整条请求路径都过去，效果才出来。

我看完这篇文章，第一反应是，AI 写代码这件事，门槛确实在往下掉。一周写出核心路径第一版，80% 以上的合并代码出自 Claude 之手，放在几年前是很难想象的。但第二反应是，难的部分也跟着换了地方。以前难在把代码写出来，现在难在证明新代码跟旧代码干的是同一件事。尤其是这种核心 API，跑偏一点点，影响的就是所有客户。

对普通开发者来说，这篇文章其实给了个挺实在的提醒：迁移语言、重构系统的时候，别只盯着测试通过率。测试是你自己出的题，生产流量才是真正的考卷。能拿到真实流量来做比对，哪怕只记差异的位置和长度，也比多写几百个测试管用。当然，前提是你得有这个条件——不是每个团队都有 Anthropic 这种量级的流量和基建。
